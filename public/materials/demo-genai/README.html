GenAI lab guide

Preparation, activities and limits of the real model.

Open the lab

Before the session

Open the lab from the project's local web server, rather than double-clicking the HTML file. The prepared local copy includes the libraries and model: no API key, subscription or account is needed. If you downloaded a lightweight kit without model weights, run node prepare-model.mjs once from this folder before starting node serve.mjs. The q4 model takes about 786 MB (749 MiB); the browser needs additional memory for the runtime and operations. Close unnecessary tabs and test the actual computer you will use during the session.

Choose Load the model, then Analyze the next token. The app tries WebGPU when a supported adapter is available; otherwise it uses single-threaded CPU/WASM. The option ?device=wasm forces CPU. First loading may take much longer on a different device. Keep the tab open after loading and do not refresh it before the demonstration.

A reproducible comparison

  1. Enter “The capital of Italy is”, set temperature to 0.8 and analyze. Inspect the actual tokens and five alternatives.
  2. Save run A. Predict what will change if you raise temperature to 1.5.
  3. Change temperature only. Softmax is recomputed from the same logits: token ranking stays the same, while probability distribution changes.
  4. Save B and compare probabilities and entropy. This comparison happens before sampling: drawing the same token twice does not disprove a distribution change.
  5. Return to 0.8, replace “Italy” with “France”, and analyze again. Context changes and a new model inference is executed.
  6. Generate one token, then a short continuation. The app runs a new inference after each generated token: the displayed probabilities always describe the next token for the current context.

Reading the results

Logits are scores produced by the model. Probabilities are calculated with softmax(logit/temperature) over the full vocabulary. The app then displays the five highest values and the remaining mass. It applies no top-k or top-p filters. Displayed values are rounded; sampling uses full values.

Temperature is positive: the slider ranges from 0.2 to 1.8. The most likely token keeps its top rank when temperature changes; a random sample may change. Temperature does not update model parameters and does not check factual truth.

The starting text is a direct completion. This lab does not apply a conversation template or a hidden system message. For clarity, each step recomputes the whole context without reusing the KV cache. This is not a benchmark of optimal model performance.

Controls and accessibility

All controls work with a keyboard. Labels, status messages and probability values are text. Bars always have an equivalent percentage. The layout becomes one column on narrow screens and at high zoom; transitions disappear when reduced motion is requested. Neither audio nor video is required to use the app.

Stop lets the current token finish and prevents subsequent steps. Each analysis allows at most 24 new tokens; input is limited to 96 tokens. Reset clears results and comparisons while keeping the model in memory. Download real data saves a JSON of the two stored runs locally.
